# HAECO MES TS 部署与人工测试指南

> 适用项目：`HAECO-MES-TS` 0.1.0  
> 适用场景：Windows 本机或局域网演示、人工验收测试  
> 当前架构：Express + SQLite 后端，Vue 3 + Vite 前端

## 1. 推荐部署方式

人工测试优先使用双进程部署：

| 服务 | 默认地址 | 说明 |
|---|---|---|
| 后端 API | `http://localhost:3000/api` | 启动时自动执行数据库迁移和种子数据初始化 |
| 前端 | `http://localhost:5173` | Vite 开发服务器，将 `/api` 代理到后端 3000 端口 |

这种方式无需额外安装 IIS 或 Nginx，适合当前 Demo 的完整功能测试。

## 2. 环境要求

- Windows 10/11 或 Windows Server。
- Node.js **22.x LTS x64（推荐）**；最低版本为 20.19.0。
- 当前 Windows Demo 环境不建议直接使用 Node 24：若 `better-sqlite3` 未命中预编译包，会回退到 `node-gyp` 源码编译并要求 Visual Studio C++ 工具链。
- npm 使用 Node.js 随附版本即可。
- 首次安装依赖时需要访问 npm registry、GitHub release 资产和 `https://cdn.sheetjs.com`。
- 确保端口 `3000`、`5173` 未被占用。
- 运行账户必须能够写入项目 `data` 目录。

在 cmd 或 PowerShell 中检查：

```bat
node -v
node -p "process.arch"
npm -v
```

预期 Node 输出为 `v22.x.x`，架构输出为 `x64`。

### 2.1 Node 版本与 `better-sqlite3`

当前项目将 `better-sqlite3` 精确固定为 **12.4.1**。该版本支持 Node 20/22/23/24，并通过 `prebuild-install` 获取 Windows x64 预编译文件；推荐使用 Node 22 LTS x64。

若日志显示 `better-sqlite3@13.0.3`，说明本地仍在使用旧版 `package.json` 或 `package-lock.json`。13.0.3 在 Windows 安装时会直接触发 `node-gyp` 本机编译，需要 Visual Studio C++ 工具链。应先同步当前项目文件，不要自行删除 lockfile。

当前机器使用的是 Node 22 解压版，安装位置为：

```text
C:\Users\Administrator\AppData\Local\Programs\nodejs-v22.23.2
```

如需重新安装：

1. 从 Node.js 官方目录下载 **Node.js 22.x Windows x64**：`https://nodejs.org/download/release/latest-v22.x/`。
2. 将完整目录放到当前用户的程序目录，并把该目录放在用户 PATH 首位。
3. 关闭并重新打开 Kiro/VS Code，使 PATH 生效。
4. 在 PowerShell 清理失败残留并重新安装：

```powershell
Set-Location "C:\Users\Administrator\Documents\project\HAECO-LGS-Demo\HAECO-MES-TS\server"
Remove-Item -Recurse -Force node_modules -ErrorAction SilentlyContinue
npm cache verify
npm ci
```

不要删除或重新生成 `package-lock.json`。若 12.4.1 在受限网络下仍无法下载预编译资产，应检查企业代理对 GitHub release 资产的访问；最后才考虑安装 Visual Studio Build Tools 2022 的“Desktop development with C++”、MSVC v143 和 Windows 10/11 SDK。

项目根目录：

```text
c:\Users\Administrator\Documents\project\HAECO-LGS-Demo\HAECO-MES-TS
```

## 3. 第一次部署

### 3.1 启动后端

打开第一个 **cmd** 窗口：

```bat
cd /d "c:\Users\Administrator\Documents\project\HAECO-LGS-Demo\HAECO-MES-TS\server"
npm ci
npm run migrate
npm run seed
npm start
```

看到以下日志即表示后端已启动：

```text
[server] listening on port 3000
[server] database: ...\data\haeco-mes-ts.db
```
说明：`npm start` 本身也会自动执行迁移和种子初始化；首次部署显式运行 `migrate`、`seed` 是为了便于观察错误。迁移与种子可重复执行，已有业务数据不会被种子覆盖。

保持该窗口运行，不要关闭。

### 3.2 启动前端

打开第二个 **cmd** 窗口：

```bat
cd /d "c:\Users\Administrator\Documents\project\HAECO-LGS-Demo\HAECO-MES-TS\web"
npm ci
npm run dev
```

浏览器打开：

```text
http://localhost:5173
```

Vite 如果发现 5173 已占用，可能自动选择其他端口，应以终端显示的 URL 为准。

### 3.3 快速检查后端

后端没有独立 `/health` 端点，可在另一个 cmd 中调用身份接口：

```bat
curl -X POST "http://localhost:3000/api/session" -H "Content-Type: application/json" -d "{\"staffNo\":\"E10001\"}"
```

预期返回 `code: 0`，并包含用户、token 等数据。

## 5. 数据与附件持久化

默认持久化位置：

```text
HAECO-MES-TS\data\haeco-mes-ts.db
HAECO-MES-TS\data\attachments\
```

必须同时备份 SQLite 数据库和附件目录。备份前建议停止后端：

```bat
mkdir D:\haeco-backup
copy "c:\Users\Administrator\Documents\project\HAECO-LGS-Demo\HAECO-MES-TS\data\haeco-mes-ts.db" "D:\haeco-backup\haeco-mes-ts.db"
xcopy /E /I /Y "c:\Users\Administrator\Documents\project\HAECO-LGS-Demo\HAECO-MES-TS\data\attachments" "D:\haeco-backup\attachments"
```

可在启动后端前通过当前 cmd 设置路径：

```bat
set "PORT=3000"
set "HAECO_MES_DB_PATH=D:\haeco-data\haeco-mes-ts.db"
set "HAECO_ATTACHMENT_DIR=D:\haeco-data\attachments"
npm start
```

环境变量仅对当前 cmd 窗口有效。开发前端的 API 代理固定指向 `localhost:3000`，因此人工测试时后端应保持 3000 端口；如修改 `PORT`，还需同步修改 `web\vite.config.js` 的代理目标。
## 6. 局域网人工测试

若其他电脑需要访问部署机，只暴露前端端口即可。后端仍在部署机本地由 Vite 代理访问。

部署机前端启动命令：

```bat
cd /d "c:\Users\Administrator\Documents\project\HAECO-LGS-Demo\HAECO-MES-TS\web"
npm run dev -- --host 0.0.0.0
```

然后在 Windows 防火墙允许 TCP 5173，在其他电脑访问：

```text
http://<部署机IP>:5173
```

可用 `ipconfig` 查看部署机 IPv4 地址。该方式仅用于受控测试网络，不建议直接暴露到互联网。

## 7. 推荐人工测试流程

### 7.1 基础连通性

1. 启动后端，确认日志显示端口和数据库路径。
2. 启动前端，打开身份选择页。
3. 输入 `E10001`，确认进入 `/task-card/list`。
4. 刷新页面，确认工卡清单仍可加载且浏览器控制台无 API 404。
5. 检查种子工卡和筛选、列设置、WFD 标识。

### 7.2 编制与审核

1. 使用 `E10001` 新增或复制一张工卡。
2. 验证 Stage 可选择，且横切 Stage 对所有类型可达。
3. 添加参考文件、工序、采集项、组件、附件及签署要求。
4. 填写变更原因并保存，确认字段级变更记录。
5. 提交审核；若校验失败，确认界面逐项显示 (a)–(g) 失败原因。
6. 切换为 `E20001`，填写审核意见并批准。
7. 确认 Effective 工卡不可直接修改，但仍可查看、打印、导出、复制、升版、作废和发布。

### 7.3 发布与 JOB

1. 使用具备 `card_release` 权限的身份打开 Effective 工卡。
2. 点击“发布至工包并进入 JOB”。
3. 确认自动进入 `/job/<jobNo>`。
4. 验证 JOB 内容来自发布快照，条码/二维码可显示。
5. 使用生产角色测试关键工序安全确认、开始/结束、采集项和电子签署。
6. 修改编制域模板后再次查看原 JOB，确认既有 JOB 快照内容不变。

### 7.4 配置与权限

1. 用 TS/Planning/Production/NDT/QA 不同身份检查按钮是否按权限点启用。
2. 确认无 `batch_replace` 权限时不能执行批量替换。
3. 确认 `config_write` 与 `capability_write` 独立控制配置页。
4. 验证非 New 工卡的编制内容在前端只读，并由后端再次拒绝写入。

### 7.5 附件和重启持久性

1. 上传一张测试图片或其他允许类型的附件。
2. 确认文件出现在 `data\attachments`。
3. 停止并重新启动后端。
4. 重新选择身份，确认新增工卡、配置和附件仍可访问。
5. 确认重启前 token 返回 401 属于当前 Demo 的预期行为。

## 9. 正式部署现状与要求

当前后端只提供 `/api`，**没有**托管 `web\dist`，也没有 SPA history fallback 或 CORS。`npm run preview` 只用于查看前端构建，不是完整的全栈生产部署。

正式部署应使用 IIS、Nginx 或同类网关，并满足：

1. 将 `web\dist` 作为静态站点根目录。
2. Vue Router 子路由找不到静态文件时回退到 `index.html`。
3. 将同源 `/api/*` 反向代理到 `http://127.0.0.1:3000/api/*`。
4. 不建议采用跨域前后端；当前后端未配置 CORS。
5. 以服务账户运行 Node 后端，并授予数据库及附件目录读写权限。
6. 配置 HTTPS、企业认证、日志轮转、定期备份和进程守护后才能作为正式生产环境。

当前 SQLite、本地附件和内存会话均为单机状态，不支持无共享存储的多实例水平扩容。正式生产前还应将 Demo 身份选择替换为企业认证。

## 10. 常见故障

### `npm ci` 安装失败

- 确认 Node.js 至少为 20.19.0。
- 确认能访问 npm registry 和 `cdn.sheetjs.com`。
- 不要复制其他机器或其他 Node 版本生成的 `node_modules`。
- Node 版本切换后，在 server、web 目录分别重新执行 `npm ci`。

### `better-sqlite3` 安装或加载失败

- 若安装日志出现 `node-gyp rebuild`、`find VS`：优先按 2.1 节切换至 Node 22 LTS x64并清理 `node_modules` 后重跑 `npm ci`。
- 若 Node 22 仍回退源码编译，检查企业代理是否拦截 GitHub release 预编译资产；也可安装 Visual Studio Build Tools 2022 的 C++ 工作负载。
- 若仅在切换 Node 版本后运行时报 ABI 不匹配，删除旧 `node_modules` 并重新执行 `npm ci`。
- 不要复制其他机器或其他 Node 版本生成的 `node_modules`。

### PowerShell 提示 `npm.ps1` 未数字签名

Node ZIP 解压版可能保留互联网区域标记，在 `RemoteSigned` 策略下会被阻止。无需降低执行策略，可任选一种方式：

```powershell
# 直接调用 cmd 启动器
npm.cmd start

# 或只解除 Node 官方启动脚本的下载标记
Get-ChildItem "C:\Users\Administrator\AppData\Local\Programs\nodejs-v22.23.2" -Filter "*.ps1" | Unblock-File
npm start
```

不要使用 `Set-ExecutionPolicy Unrestricted`。本机 Node 目录中的启动脚本已解除标记。

### 后端提示 `EADDRINUSE: 3000`

3000 端口已占用。停止占用进程，或同时修改后端 `PORT` 与 `web\vite.config.js` 的代理目标。

查看端口：

```bat
netstat -ano | findstr :3000
```

### 页面能打开但 API 请求失败

- 确认后端窗口仍在运行且监听 3000。
- 确认前端代理目标没有被修改。
- 不要直接双击打开 `web\dist\index.html`。
- 正式静态站点必须配置 `/api` 反向代理。

### 数据库或附件提示无权限

确认运行账户对数据库父目录、数据库文件和附件目录具有读写权限。作为 Windows 服务运行时，服务账户可能不同于当前登录用户。

### 登录后突然出现 401

后端重启会清空内存 session。返回身份选择页重新输入 Staff No。

### 重跑 seed 后配置没有恢复默认值

种子采用“存在则跳过”，不会覆盖已经存在的配置或业务数据。`seed` 不是数据库重置脚本，不要通过删除生产数据库来恢复配置。

### 刷新 `/job/...` 或 `/config` 返回 404

Vite 开发服务器通常能处理该场景；正式静态服务器必须配置 SPA fallback 到 `index.html`。

## 11. 停止服务

在前端和后端各自的 cmd 窗口按 `Ctrl+C`。后端停止后再进行数据库文件级备份。

## 12. 当前限制

- 身份认证仅用于 Demo，无密码、过期策略和企业 SSO。
- 会话保存在后端内存，服务重启后失效。
- 数据库迁移当前基于 `IF NOT EXISTS`，不是带版本号的增量迁移框架。
- 正式静态托管、HTTPS、进程守护、集中日志和监控需由部署环境提供。
- Vite 构建存在大 chunk 警告，但不阻断人工测试。
