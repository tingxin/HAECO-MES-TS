## 1. 裁决原则

客户 Demo 是后期业务细节和交互参考，不是正式状态机、数据架构或安全模型。与既有蓝图及已裁定规则冲突时，以当前正式规格为准。NRC、Work Package、TPC、SWS 只保留既有接口触点，不扩展为本轮主体。

## 3. 明确不吸收

- Demo 四态 `Draft/Pending/Active/Obsolete`：保持 `New/UnderReview/Effective/Superseded/Void`。
- Withdraw、Draft 直接 Delete：不加入正式迁移；作废继续执行前置校验与留痕。
- Level 2/双节点审批：保持 TS Manager 单节点、一编一审、意见必填。
- 类型 12–14：工卡主类型仍为 01–11。
- `R01/R02` 存储：保持整数存储，UI/打印显示 `01/02`。
- 编制态 Job No、二维码和 View 即显示执行字段：只在 JOB 上下文呈现，条码只在释放后生成。
- `0010/0020` 工序号：保持 `A…Z, AA…`。
- Demo browser-only、CDN、mock、HTML `.xls`/ZIP：不作为正式架构。
- Demo 缺失的 FAI、签署、安全警示、审核门禁、分类确认、作废前置和权限审计不得删除。
## 4. 保守裁决与待澄清

| 项目 | 本轮可运行裁决 | 后续待确认 |
|---|---|---|
| 高级筛选组合 | 工序 Skill 与 Description 同时填写时要求同一道工序同时命中；总数在分页前计算 | 最终统计与搜索性能 SLA |
| 导出命名/格式 | 保留现有关键/全量 CSV；本轮只正式化批量打印 | Batch Export / Export Report 最终名称及 xlsx 格式 |
| 历史恢复 | 不提供，禁止覆盖历史版本 | 若提供，只能基于快照新建 New 版本 |
| 双版本打印 | 不提供 | 是否属于受控输出 |
| Excel 导入 | 文件上传保留；追加默认，覆盖需确认和原因 | 是否并存剪贴板 TSV 导入 |
| 最后工序 | 至少保留一道，服务端强制 | 新卡是否可暂时零工序 |
| 附件复制 | 复制 payload/annotations，复用不可变附件二进制 | 是否需要物理复制附件及独立保留策略 |
| 图片标注 | 原附件 + 结构化 annotations；预览/打印渲染标注 | 是否另存派生图及保存期限 |
| 正式打印 | 沿用当前模板和逐卡分页 | 客户纸质样张仍未提供 |

- 后端：筛选领域与仓储 SQL、版本快照/Diff 服务、工序复制/插入/删除保护/原子导入、打印与 JOB 快照 payload。
